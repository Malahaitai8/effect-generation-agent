# 生日车窗特效生成链路试跑记录

## 试跑说明

- 输入视频：`录屏2026-08-20 16.52.56.mov`
- 视频时长：约 8.94 秒
- 本次目标：按照七步链路模拟完成一次热点特效拆解，验证从视频理解到生产链路设计是否能够顺畅衔接。
- 本次范围：不执行 RAG，不实际调用生图或生视频模型；完成分析、链路设计、素材规划、Prompt 草案和静态可行性判断。
- 说明：原视频是录屏，黑边、鼠标和页面元素均视为录屏噪声，不属于目标特效。

## Step 1：视频客观理解

### 1.1 事实叙事

画面固定拍摄一辆白色或银色汽车的侧面车窗。开始时车窗关闭，玻璃上显示白色的“Happy”字样，车内人物手持点燃的生日蜡烛。随后车窗缓慢下降，“Happy”随玻璃向下移出画面，人物和蜡烛被完整露出。人物对着蜡烛吹气，将火焰吹灭。之后车窗重新升起，玻璃上出现“Birthday”字样，最后车窗关闭并停留在该状态。

### 1.2 时间线

| 时间 | 客观画面 |
|---|---|
| 约 0–2 秒 | 车窗关闭；玻璃显示“Happy”；人物和点燃的蜡烛位于玻璃后方。 |
| 约 2–4 秒 | 车窗下降；“Happy”随玻璃下移；人物和蜡烛逐渐被完整露出。 |
| 约 4–5.5 秒 | 人物面向蜡烛吹气，火焰熄灭。 |
| 约 5.5–8.5 秒 | 车窗上升；玻璃显示“Birthday”；人物重新被玻璃遮挡。 |
| 约 8.5–8.94 秒 | 车窗关闭，以“Birthday”字样作为结束画面。 |

### 1.3 结构化观察

- 主体：车内单人，手持生日蜡烛或带蜡烛的小蛋糕。
- 场景：汽车侧面车窗，外部固定机位。
- 核心动作：车窗下降、人物吹灭蜡烛、车窗上升。
- 表情与状态：人物等待、吹气、完成后微笑或放松。
- 视觉元素：白色车身、深色车窗、白色英文手写字、蜡烛火焰。
- 镜头：基本固定，无明显切镜，主体变化来自车窗和人物动作。
- 状态变化：`Happy / 车窗关闭 / 火焰点燃` → `人物露出 / 吹蜡烛` → `Birthday / 车窗关闭 / 火焰熄灭`。
- 叙事结构：利用车窗升降完成文字切换和人物揭示，形成一句“Happy Birthday”的分段生日祝福。

### 1.4 观察结果

Step 1 可以独立回答“看到了什么”，并能输出后续链路判断所需的动作、时序、文字和状态变化信息。本步骤不判断其卖点，也不决定生产方式。

## Step 2：业务判断

### 2.1 主卖点

主卖点暂定为“前后状态变化”：车窗的升降把“Happy”、真人吹蜡烛和“Birthday”串成一次完整的生日揭示。

判断依据：如果只保留人物吹蜡烛而去掉车窗文字和前后状态，原视频最有辨识度的结构会消失。

### 2.2 次卖点

次卖点为“具体动作与节奏”：人物出现后在正确的时间吹灭蜡烛，随后车窗再升起。

次卖点用于补充说明，不要求每个任务都必须存在。本例中它与主卖点相互配合，因此保留。

### 2.3 用户复刻诉求

用户希望把自己或指定人物替换到车内，同时保留：

- 车窗先降后升的完整过程；
- “Happy”与“Birthday”的前后呼应；
- 人物露出后吹灭蜡烛的动作；
- 原视频的镜头位置、节奏和生日氛围。

### 2.4 当前不确定项

- 模型能否稳定生成拼写准确、位置稳定的“Happy”和“Birthday”。
- 模型能否同时保持人物身份、车窗结构和蜡烛火焰状态。
- 用户认为最重要的是“生日文案揭示”，还是“吹蜡烛动作复刻”；需要通过实际结果判断权重。

## Step 3：执行链路类型选择

### 3.1 关键控制要求

- 需要复刻连续动作及其先后节奏，而不只是首尾两个视觉状态。
- 需要保留车窗、人物、文字和火焰之间的空间关系。
- 需要保持固定镜头下的完整叙事顺序。
- 需要用用户人物替换原人物，并尽量保持身份一致性。

### 3.2 RAG 主召回

本次为首轮可行性试跑，按约定跳过 RAG。正式执行时应在此构造一次主召回查询，并保存任务级案例快照，供后续步骤按需参考。

建议的主召回语义包括：车窗升降、前后文字变化、人物揭示、吹蜡烛、固定镜头、连续动作复刻、人物身份保持。

### 3.3 链路选择

选择：**参考视频驱动**。

理由：单图驱动难以提供车窗升降、吹蜡烛和文字切换的精确时序；多图驱动可以描述首尾状态，但不足以稳定表达中间连续动作。原热点视频本身是最完整的动作、镜头和节奏参考。

预期基础结构：

`用户人物图 + 热点参考视频 + 动作复刻 Prompt → 参考视频生成模型 → 结果视频`

### 3.4 主要风险

- 英文文字可能错拼、变形或漂移。
- 车窗边缘和玻璃升降结构可能发生形变。
- 人物面部可能因玻璃遮挡、吹气动作而失真。
- 蜡烛火焰的“点燃—熄灭”状态可能不准确。
- 模型可能把录屏黑边、鼠标或水印误当作参考内容。

## Step 4：具体链路设计、模型选择与素材规划

### 4.1 最小可行链路

本轮建议先验证最短链路，不预先增加过多节点：

1. 输入用户单人图，并检查人脸清晰度与可用性。
2. 清理热点视频中的录屏噪声，保留有效画面与原始时间顺序。
3. 将用户图作为人物参考、热点视频作为动作与镜头参考，调用参考视频生成模型。
4. 输出候选视频，人工检查身份、车窗、文字、动作和节奏。

### 4.2 模型选择

候选模型：**Kling 3.0 Omni** 或其他同时支持人物图与视频参考的模型。

选择理由：本任务需要视频级动作参考和人物身份参考，普通首帧生视频不足以承载完整时序。

说明：具体接口是否支持所需输入组合、参考强度和 8–9 秒时长，需在真实调用前确认；当前模型名称只作为验证候选，不作为已确认能力。

### 4.3 素材清单

- 必需：用户正脸清晰的单人图。
- 必需：裁掉录屏黑边和界面噪声后的热点参考视频。
- 分析辅助：起始“Happy”、人物与蜡烛、吹蜡烛、结尾“Birthday”四张关键帧。
- 可选：若人物身份保持不足，可补充同一人物的半身参考图。

### 4.4 是否需要额外节点

第一轮不增加独立生图节点。只有当直接参考视频生成无法稳定获得“人物位于正确车内位置”的结果时，再考虑先生成构图匹配的车内人物参考图。

如果模型始终无法稳定生成准确文字，后续应把文字从生成任务中拆出，改为跟随车窗运动的后期合成；这属于核心链路验证后的稳定性优化。

## Step 5：热点素材提取与标准化

### 5.1 本轮提取结果

- 已按时间线抽帧并确认完整叙事。

- 热点视频本身仍是参考视频驱动的主要素材，关键帧用于理解和验收，不直接替代参考视频。

## Step 6：基于案例快照的 Prompt 写作

本次未执行 RAG，因此 Prompt 直接依据 Step 1–5 编写。正式流程中应从任务级案例快照按需读取相似节点的 Prompt 经验；只有出现明确覆盖缺口时才补充召回。

### 6.1 生成 Prompt 草案

> 使用输入人物图中的人物替换参考视频中的人物，严格保持人物的面部身份、发型和主要外观特征。复刻参考视频的固定侧面机位、白色或银色汽车车门、车窗升降速度和完整动作节奏。开始时车窗完全关闭，深色玻璃上以清晰、稳定、拼写准确的白色手写字体显示“Happy”，人物在玻璃后手持一支点燃的生日蜡烛。随后车窗平稳下降，“Happy”随玻璃向下移动并离开画面，人物和蜡烛逐渐完整露出。人物自然微笑并对准蜡烛吹气，火焰随即熄灭。之后车窗平稳升起，玻璃上以同样清晰、稳定的白色手写字体显示“Birthday”，最终车窗完全关闭并停留。全程保持同一人物、同一汽车结构、同一构图和连续自然的运动，不切镜。

### 6.2 负向约束

> 不改变人物身份，不增加人物、手臂或手指；不改变车门和车窗结构；车窗不得弯曲、破裂或穿过人物；“Happy”和“Birthday”不得错拼、乱码、漂移或粘在背景上；蜡烛只能在吹气后熄灭；不要移动镜头，不要切镜，不要生成黑边、鼠标、平台界面、水印或无关文字。

### 6.3 Prompt 能力边界

文字准确性是本例最明显的风险。Prompt 可以表达要求，但不能保证生成模型稳定拼写英文。若实测失败，不应持续堆叠 Prompt，而应考虑生成无字玻璃版本，再通过运动跟踪把“Happy”和“Birthday”合成到玻璃上。

> 使用输入人物图中的人物替换参考视频中的人物，严格保持人物的面部身份、发型和主要外观特征。复刻参考视频的固定侧面机位、白色或银色汽车车门、车窗升降速度和完整动作节奏。开始时车窗完全关闭，深色玻璃上以清晰、稳定、拼写准确的白色手写字体显示“Happy”，人物在玻璃后手持一支点燃的生日蜡烛。随后车窗平稳下降，“Happy”随玻璃向下移动并离开画面，人物和蜡烛逐渐完整露出。人物自然微笑并对准蜡烛吹气，火焰随即熄灭。之后车窗平稳升起，玻璃上以同样清晰、稳定的白色手写字体显示“Birthday”，最终车窗完全关闭并停留。全程保持同一人物、同一汽车结构、同一构图和连续自然的运动，不切镜。不要增加人物或肢体，不要改变车窗结构，不要生成错字、乱码、黑边、鼠标、平台界面、水印或无关文字。

### 5. 最终判断

**可进入真实生成验证。** 当前已验证的是七步分析和链路设计的完整性；尚未验证模型实际生成质量。设计师方案与本次方案在链路类型和核心输入上高度一致，说明当前流程的主要判断是有效的。第一轮测试应保留本次独立产出的链路和 Prompt，优先观察连续动作与人物身份是否成立，再判断文字是否需要从生成模型中拆出做后期合成。
