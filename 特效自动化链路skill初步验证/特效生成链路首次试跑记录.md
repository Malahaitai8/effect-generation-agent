# 特效生成链路首次试跑记录

## 0. 试跑说明

- 输入视频：`录屏2026-08-20 15.46.53.mov`
- 视频规格：6.62 秒，1198 × 1072，约 60 fps
- 验证目标：不接 RAG，按七步流程验证从视频理解到生产链路输出是否能够闭环
- 本轮范围：完成视频分析、链路设计、关键帧提取、Prompt 草拟和静态校验
- 本轮未执行：RAG 召回、真实用户图生图、真实视频模型生成

本次输入是带播放器界面的录屏，不是原始热点视频。视频开头和结尾存在暂停按钮、顶部界面文字等录屏元素，分析时已将这些内容视为非热点内容。

## Step 1：视频客观理解

### 1.1 事实叙事

一名年轻女性身穿粉蓝配色的古风长裙，头戴粉色花饰，站在发光的水晶拱桥上。背景是蓝紫色星空、云层和暖色天光。人物先转身并舒展双臂，长发和宽袖随动作摆动；镜头逐渐拉远，粉色花瓣在人物身后汇聚成巨大的发光心形，随后心形散开成大量花瓣，花瓣向画面四周和镜头前方飘落。最终画面停留在人物站在桥上的全景。

### 1.2 时间线

| 时间 | 客观内容 |
|---|---|
| 0.0–0.5s | 录屏播放器处于起播阶段，短暂出现暂停画面和播放按钮；非热点内容本身 |
| 0.5–1.5s | 人物近景转身，长发和宽袖产生明显甩动；背景保持星空云层 |
| 1.5–2.5s | 人物转回正面并舒展双臂，镜头从近景向中景过渡 |
| 2.5–3.5s | 粉色花瓣在人物身后汇聚，逐渐形成发光心形轮廓 |
| 3.5–5.0s | 心形花瓣扩大并稳定呈现，人物保持正面姿态，镜头继续拉远 |
| 5.0–6.0s | 心形逐渐散开，大量花瓣向画面四周及镜头前景飘落，桥体全景显现 |
| 6.0–6.62s | 画面停留在人物与拱桥全景，播放器控件再次出现 |

### 1.3 结构化特征

- 主体：单人年轻女性
- 服装：粉蓝色古风长裙，金色胸前装饰，宽大长袖
- 发型：黑色长发，双侧发髻，粉色花朵发饰
- 场景：蓝色发光水晶拱桥、星空云层、暖色天光
- 动作：转身、展开双臂、抬头、站立展示
- 表情：轻微微笑，整体平静柔和
- 视觉元素：粉色花瓣、发光心形、星云、发光桥体
- 镜头：近景/中景逐渐拉至全景，无明显硬切
- 状态变化：主体服装和身份不变；花瓣由无到汇聚成心形，再散开
- 情绪基调：浪漫、梦幻、古风、唯美

### 1.4 Step 1 结果

视频故事和时间线能够被稳定描述。需要注意：如果输入是录屏，应先识别并排除播放器控件、鼠标和页面文字，否则可能污染关键帧选择及 Prompt。

## Step 2：业务判断

### 2.1 主卖点

`visual`：浪漫梦幻的古风人物形象与星空水晶桥场景。

### 2.2 次卖点

`transformation`：粉色花瓣在人物身后汇聚成心形，再散开形成漫天花瓣。

次卖点在本案例中有必要保留，因为它直接决定视频节点的时间顺序和特效 Prompt。

### 2.3 用户复刻诉求

用户希望将自己的形象转换成同类古风人物，置于梦幻水晶桥和星空场景中，并生成“转身展示—花瓣成心—花瓣散开”的浪漫动态效果。

### 2.4 判断依据

- 人物、服装和场景贯穿全片，占据主要视觉注意力
- 主体没有发生变装或身份变化
- 心形花瓣是最明显的动态记忆点，但依附于整体古风视觉设定
- 人物动作较简单，不以精准舞蹈或动作复刻为核心

### 2.5 不确定项

- 如果实际热点数据表明“花瓣成心”比古风造型更受关注，主卖点也可能被判断为 `transformation`
- 本轮没有标题、配乐、互动评论等外部信息，仅根据视频画面判断

## Step 3：执行链路类型选择

### 3.1 关键复刻信息与控制要求

**视觉状态**

- 必须保留古风人物造型、粉蓝服装、花饰发型、水晶桥和星空场景
- 主体从开始到结束保持同一种视觉状态，不需要准确控制多个角色状态

**时序表演**

- 需要表现人物轻柔转身、长发和宽袖摆动
- 需要按顺序表现花瓣汇聚成心形，再散开飘落
- 动作简单，可以用文字 Prompt 描述，不必精准复刻原视频中的每个动作帧

**叙事与镜头**

- 镜头需要从人物近景平滑拉远到桥体全景
- 无复杂剪辑和场景切换

### 3.2 RAG

本轮跳过 RAG，不生成案例快照。目的是先验证没有历史案例辅助时，核心链路能否成立。

### 3.3 链路类型

选择：**单图驱动**。

理由：

- 只需要显式控制一个关键视觉状态
- 人物动作、镜头拉远和花瓣特效可以通过视频 Prompt 描述
- 不需要用多张图控制前后人物状态
- 不要求精准复刻一段复杂舞蹈或表演，因此参考视频不是必要输入

### 3.4 风险

- 单图视频模型未必能稳定生成结构清晰的心形花瓣
- “先汇聚、后散开”的时序可能不稳定
- 镜头拉远、人物一致性和桥体结构需要同时保持，对视频模型有一定压力
- 如果实际测试中上述问题明显，应比较参考视频驱动，而不是在当前阶段直接增加复杂链路

## Step 4：具体链路设计、模型选择与素材规划

> 模型名称沿用现有方案中的候选模型，仅作为模拟设计；本轮没有调用模型 API，也没有核验线上版本和参数支持情况。

### 4.1 节点序列

| 节点 | 用途 | 输入 | 候选模型 | 输出 |
|---|---|---|---|---|
| Node 1：人物古风化 | 保留用户身份，生成粉蓝古风人物形象 | 用户单人照片、人物造型参考帧 | 可图 2.1 人像参考 | 古风人物图 |
| Node 2：场景融合与首帧生成 | 将人物放入水晶桥和星空场景，生成视频首帧 | Node 1 输出、场景/特效参考帧 | nano2 | 完整视频首帧 |
| Node 3：首帧生视频 | 生成人物转身、花瓣成心并散开的完整视频 | Node 2 输出 | Kling Omni 3.0 | 约 5–6 秒结果视频 |

### 4.2 节点依赖

```text
用户照片 + 人物造型参考
        ↓
Node 1：古风人物图
        ↓ + 场景/特效参考
Node 2：完整视频首帧
        ↓
Node 3：结果视频
```

### 4.3 基础素材规划

- 人物造型参考：约 2.0 秒，正面人物、服装和发饰较清楚
- 场景/特效参考：约 4.0 秒，人物全身、水晶桥和心形花瓣同时出现
- 用户输入照片：本轮未提供，真实执行时必需

### 4.4 Step 4 结果

三节点链路逻辑成立。Node 1 和 Node 2 是否需要拆开，需要实际测试模型对“身份保持 + 服装转换 + 场景融合”的承载能力后确定；如果单个模型能够稳定完成，也可以合并成一个首帧生成节点。

## Step 6：Prompt 写作

本轮不使用案例快照，直接根据视频理解、链路设计和实际素材编写 Prompt。

### Node 1：人物古风化 Prompt

```text
以输入人物照片为身份参考，严格保留人物可辨识的五官结构、脸型和整体气质。参考造型图，将人物转换为梦幻古风女性角色：黑色长发，双侧古典发髻，佩戴粉色花朵发饰和金色小饰品；穿粉蓝渐变古风长裙，浅粉宽袖、蓝色披帛、胸前金色装饰。正面自然站立，人物完整、比例正常，服装纹理清晰，柔和微笑，浪漫唯美，高质量人像，避免背景和复杂特效。
```

约束：

```text
不要改变人物身份；不要生成多个人；不要增加多余肢体；不要改变服装主色；不要出现文字、水印和播放器界面。
```

### Node 2：场景融合与首帧 Prompt

```text
保留输入人物的面部身份、发型、粉蓝古风长裙和金色服饰细节。将人物完整放置在一座通透发光的蓝色水晶拱桥中央，背景为深蓝紫色星空、绚丽云层和暖色天光，水面反射桥体光芒。人物正面站立，双臂自然轻微展开，构图由中景到全身，主体居中，桥体结构完整，空间层次清晰。整体风格梦幻、浪漫、精致，适合作为视频生成首帧。首帧暂不出现大面积花瓣心形，只保留少量粉色花瓣作为后续动画铺垫。
```

约束：

```text
保持人物身份和服装一致；桥体不要断裂；不要增加第二个人物；不要提前遮挡人物；不要出现文字、水印和播放器控件。
```

### Node 3：首帧生视频 Prompt

```text
人物站在发光的蓝色水晶拱桥中央，先轻柔转身并缓慢展开双臂，黑色长发、粉色宽袖和蓝色披帛随动作自然飘动。镜头稳定、平滑地从人物中景逐渐向后拉远。粉色花瓣从人物身后和画面两侧汇聚，在人物背后形成一个巨大、轮廓清晰、柔和发光的心形；心形短暂停留后逐渐散开，化为大量花瓣向四周和镜头前方飘落。人物始终保持面部清晰、身体结构稳定、服装一致，水晶桥和星空云层保持连续，整体氛围浪漫、梦幻、唯美。全程无硬切，动作连贯，约 5–6 秒。
```

负向约束：

```text
避免面部变形、人物闪烁、服装变色、额外肢体、桥体扭曲、心形结构破碎、花瓣完全遮挡面部、镜头抖动、突然切镜、文字、水印和播放器控件。
```

### Step 6 结果

Prompt 已覆盖人物动作、镜头、花瓣成心和花瓣散开的顺序。能否在一次首帧生视频中稳定完成，仍需真实模型验证。

| 具体节点完整性 | 通过 | 输入输出和依赖关系完整 |
| 基础素材 | 通过 | 已提取造型参考和场景/特效参考 |
| Prompt 完整性 | 通过 | 覆盖人物、场景、动作、镜头和特效时序 |
| 模型能力支持 | 待确认 | 本轮未读取真实模型能力配置，也未调用模型 API |
| 最终生成质量 | 未验证 | 尚未执行图生图和视频生成 |

### 7.2 本轮结论

七步流程在“分析和方案生成”层面能够形成完整闭环，整体方向可行。该案例说明：即使不接 RAG，也能够从视频事实理解推进到链路类型、具体节点、素材和 Prompt。

但本轮只能证明“方案能够被设计出来”，还不能证明“方案能够稳定生成目标效果”。下一轮最值得验证的是：

1. Node 1/Node 2 对用户身份和服装的保持能力
2. 单图生视频能否稳定完成花瓣汇聚成清晰心形再散开的时序
3. 镜头拉远时人物、桥体和服装是否保持一致
4. Node 1 与 Node 2 是否有必要拆成两个生图节点
5. 不接 RAG 时生成的 Prompt，与设计师实际生产 Prompt 的差距

### 7.3 建议记录为待验证项

- 主卖点确认是否需要结合视频外信息
- 关键帧密集选优策略
- 模型能力配置和参数合法性
- 心形花瓣时序控制的稳定性
- RAG 是否能显著改善节点设计与 Prompt 质量

### 3. 关键修正

#### 3.1 链路类型应改为多图驱动

本次模拟将“人物服装和身份始终一致”理解为只有一个关键视觉状态，因此选择了单图驱动。设计师版本说明，这个判断维度不完整。

关键视觉状态不仅包括人物身份、服装和场景，还包括需要精确控制的镜头构图：

- 状态 1：人物面部或半身近景
- 状态 2：人物站在拱桥上的全身远景

由于视频需要从近景稳定过渡到全景，且两个构图都需要被明确控制，因此该案例更适合多图驱动。

Step 3 的控制要求判断需要补充：

> 除人物外观和场景状态外，还要判断是否存在两个或多个必须准确控制的景别、构图或镜头状态。如果近景和全景都需要精确呈现，应视为多状态控制，并优先考虑多图驱动。

#### 3.2 具体链路应增加性别识别

设计师版本为男性和女性分别生成造型及视频 Prompt。若特效需要同时支持不同性别用户，则性别识别是必要的路由节点。

修正后的节点为：

```text
Node 1：性别识别
        ↓
Node 2：生成对应性别的古风人物近景图
        ↓
Node 3：生成对应性别的桥上人物全景图
        ↓
Node 4：图 1 + 图 2 多图生视频
```

#### 3.3 关键帧选择应服务于两个构图状态

关键帧不应只被定义为“造型参考”和“特效参考”，而应分别选择：

- 近景关键帧：用于描述人物面部、发型、服装上半身和视频起始构图
- 全景关键帧：用于描述人物全身、桥体、背景和镜头拉远后的目标构图
- 花瓣心形阶段：可以作为视频 Prompt 的动态效果参考，不一定单独生成第三张输入图

本轮提取的 2.0 秒和 4.0 秒参考帧仍有价值，但后续应进一步在人物近景阶段密集抽帧，选择更接近设计师图 1 构图的清晰帧。

### 5. 初步可行性结论

#### 已得到初步验证的部分

- 七步流程能够从视频客观理解推进到卖点、控制要求、链路和 Prompt
- 对热点叙事、视觉卖点和花瓣动态效果的理解与设计师方案基本一致
- 关键帧确实可以支持人物近景、人物全景和花瓣效果的分析
- 设计师链路提供了完整模型、节点和 Prompt，说明该效果在生产设计层面具备可执行性
- “先生成关键状态图，再生成视频”的总体思路成立

#### 本次模拟暴露的问题

- 链路类型选择规则遗漏了“景别和构图变化也属于关键视觉状态”
- 单图驱动无法像设计师的双图方案一样明确控制近景起点和全景终点
- 模拟版本缺少性别识别及男女 Prompt 路由
- 模拟版本使用了两个不同的生图模型，设计师版本表明同一人像参考模型即可覆盖近景和全景
- 仅根据人物外观是否变化判断单图/多图，会低估镜头叙事对多状态控制的需求

#### 当前结论

> 整体七步方案初步可行，但 Step 3 的链路类型判断规则需要修正。该案例应从“单图驱动”调整为“多图驱动”：分别生成近景人物图和桥上全景图，再通过 Kling 3.0 Omni 完成旋转、镜头拉远和花瓣特效。设计师版本比本次模拟版本更完整，也更符合实际生产要求。
