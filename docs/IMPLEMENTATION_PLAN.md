# 实施顺序

本计划已确认。目标是先形成一个能完整运行、支持单图驱动和参考视频驱动的 Agent 初版，再通过端到端测试调优。

## 顺序

1. 固定任务结果 schema。
2. 完成 `chain-single-image.md`。
3. 完成 `chain-reference-video.md`。
4. 结构化录入两类代表 case。
5. 完成 `case-schema.md`。
6. 完成 `case-retrieval.md` 和任务级案例快照格式。
7. 完成 `chain-selection.md`。
8. 完成 `chain-design.md` 与模型能力配置。
9. 补齐 Step 1、2、5、7 的最小模板。
10. 串联 Agent 编排和 `SKILL.md`，实现检索脚本。
11. 执行单图链路端到端试跑。
12. 执行参考视频链路端到端试跑。
13. 根据试跑结果调优，再评估多图驱动。

## MVP 验收标准

- Step 1–7 均有明确输入、输出和失败状态。
- Step 3 只执行一次主召回，并保存任务级案例快照。
- Step 4 负责节点、模型和素材规划，不提前写最终 Prompt。
- Step 5 先获得或确认实际素材。
- Step 6 基于实际素材与案例快照生成节点 Prompt。
- 单图和参考视频需求能够选择正确链路并输出可执行生产方案。
- 多图需求返回明确的暂不支持结果，不被错误归入单图链路。
- 所有事实、推断、风险和缺失项可追溯。

## 当前阶段

项目脚手架完成后，从第 1 项开始实施。
